# TG Knowledge Bot

Telegram group knowledge base builder. Connects to a Telegram group via your personal account (MTProto), analyzes messages, builds a searchable knowledge base with deduplication and quality scoring based on user reputation and answer completeness.

## Architecture

```
Telegram Group (~3K users)
       │
       ▼  MTProto (gramjs)
  Ingestor ──► SQLite (raw messages)
       │
       ▼  BullMQ classify queue
  Classify Worker (LLM: question/answer/discussion/noise)
       │
       ▼  BullMQ embed queue
  Embed Worker (vector embeddings via AI SDK)
       │
       ▼  if answer → BullMQ kb queue
  KB Worker (dedup + quality → knowledge base)
       │
       ▼
  Knowledge Base (SQLite + embeddings)
       │
       ▼
  Query Interface (/ask → semantic search → LLM synthesis)
```

## Quick Start

```bash
# 1. Clone and install
git clone https://github.com/kilogramirisok/tg-knowledge-bot.git
cd tg-knowledge-bot
pnpm install

# 2. Configure
cp .env.example .env
# Edit .env with your credentials (see below)

# 3. Generate Telegram session (requires API keys from https://my.telegram.org)
pnpm run auth

# 4. Test with seed data (no Telegram or Redis needed)
pnpm run seed    # populate test messages (8 users, 20 msgs)
pnpm run analyze # run analysis pipeline (creates ~8 KB entries)

# 5. Production (needs Redis)
docker compose up -d
# Or without Docker:
pnpm run dev -- --mode=all
```

## Modes

- `--mode=seed` — Populate DB with test data (Spanish tax/nomad messages)
- `--mode=analyze` — Batch-process all unprocessed messages (no queue needed)
- `--mode=ingest` — Start MTProto ingestor only (reads from Telegram)
- `--mode=worker` — Start BullMQ workers only (classify + embed + KB)
- `--mode=reputation` — Recalculate user reputation scores
- `--mode=query` — Interactive terminal query interface
- `--mode=all` — Run all services (ingestor + workers + reputation cron)

## Environment Variables

- `TELEGRAM_API_ID` — From https://my.telegram.org (for ingest)
- `TELEGRAM_API_HASH` — From https://my.telegram.org (for ingest)
- `TELEGRAM_SESSION` — Generated by `pnpm run auth` (for ingest)
- `TARGET_GROUP` — Group username, default: `taxesnomadspain`
- `DATABASE_PATH` — SQLite path, default: `./data/knowledge.db`
- `LLM_BASE_URL` — OpenAI-compatible API base URL, default: `https://openrouter.ai/api/v1`
- `LLM_API_KEY` — API key for LLM provider (OpenRouter, OpenAI, etc.)
- `LLM_MODEL` — Model name, default: `google/gemini-2.0-flash-001`
- `EMBEDDING_MODEL` — Embedding model, default: `text-embedding-3-small`
- `REDIS_URL` — Redis connection, default: `redis://localhost:6379`
- `LOG_LEVEL` — `debug`/`info`/`warn`/`error`, default: `info`

## Tech Stack

- **TypeScript** compiled with **tsgo** (`@typescript/native-preview`)
- **pnpm** with 4-day minimum package age (supply-chain protection)
- **Vercel AI SDK** + **OpenRouter** — LLM calls (classification, quality scoring, query synthesis)
- **gramjs** (`telegram`) — MTProto client (personal account, no bot permissions needed)
- **Drizzle ORM** + **better-sqlite3** — database with drizzle-kit migrations
- **BullMQ** + **ioredis** — job queue (classify → embed → KB pipeline)
- **Vector similarity** — embeddings stored as JSON, brute-force cosine similarity

## Queue System

Three BullMQ workers process messages asynchronously:

- **classifyWorker** — concurrency 3, rate-limited 10/sec → LLM classifies message type
- **embedWorker** — concurrency 2 → generates vector embedding → answers go to KB queue
- **kbWorker** — concurrency 1 (serial dedup) → quality score + dedup → KB insert/update

Workers handle SIGTERM/SIGINT gracefully. Jobs retry with exponential backoff (3 attempts for classify/KB, 2 for embed).

## Scoring

### KB Inclusion
```
final = quality × 0.40     (LLM-judged completeness)
      + reputation × 0.25  (user activity + expertise signals)
      + community × 0.20   (reactions received, capped at 20)
      + 0.15               (base score)
```
Threshold: 0.50 — below this, answer is rejected from KB.

### Deduplication
- Embeddings compared via cosine similarity
- `\> 0.85`: existing entry found — update if new score is higher, else skip
- `\< 0.85`: new KB entry created

### User Reputation
```
reputation = 0.30 × activity_consistency
           + 0.25 × expertise_signals (reactions on answers)
           + 0.25 × curation_rate     (answers accepted into KB)
           + 0.20 × recency           (7-day half-life)
```

## Database Migrations

Schema is defined in `src/db/schema.ts` (single source of truth).

```bash
# Generate migration after schema change
pnpm run db:generate

# Apply migrations (also runs automatically on startup)
pnpm run db:push
```
